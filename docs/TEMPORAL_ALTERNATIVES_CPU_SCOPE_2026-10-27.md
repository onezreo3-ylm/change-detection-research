# 互斥时间动作的显式CPU机制检查

2026-10-27，真实四区域探针出分前。备用提案由概念筛查进入单独的合成机制可证伪检查，
不代表完整近邻审查完成或新方法准入。当前GPU评价→分析→原冻结探针队列不变；
不新增研究GPU任务、模型拟合、专家、图像几何变换、数据访问或真实checkpoint加载。

使用原共享ResNet18/FPN64/GN8及同一个stage2adapter。明确CPU/FP32、1个256输入对、
固定seed20261027、2线程、随机权重；仅为避免零动作fixture，将adapter末层一次设为
std0.01非零随机权重，所有比较共享该初值，没有优化或按分数重选fixture。
从同一实际编码A/B和各一次adapter调用构造A-only/B-only/both的绝对差候选。
四个区域沿用提案的固定[2:8]/[24:30]角部位置，仅feature动作，不变换原输入图像。

捕获同一无动作GN参考。分别实际解码全部区域A-only、B-only、both；再实际执行全部
4^4=256种局部合法选择，核对是否与上述三个输出按支持拼合bit-exact。另测仅从all-both
输出直接拼合A-only是否失败；这仅排除该具体拼合控制，不是信息论或计算下界。
交换输入A/B后单独捕获新参考，核对A/B动作身份对应、both/noop不变。该对称性已有近邻。
模型完整张量hash、hooks移除、实际encoder/adapter/decoder调用和非平凡变化均记录。

成本按每个观测对所执行的decoder视图报告：baseline+3variants为4，baseline+selected
为2；这不是Python调用数下界。三个variants可沿batch维打包，也可能共享/稀疏计算，
不能由调用数量推断延迟。未来GPU控制须报告实际batch、视图、FLOPs、显存和全墙钟，
保持评价精度并先核验数值身份。当前没有速度、新颖性或真实任务收益主张。

原604项项目测试在该检查前已通过，原模型/library及两个已封存GPU运行源均保持。
本检查源码与结果保存在新runs目录，不作为真实数据wrapper。若以后移入运行模块，
须另外实现样本/参考/动作绑定、完成工程验收和全项目测试；不能直接接真实数据。
